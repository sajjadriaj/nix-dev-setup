# nix-dev-setup

Reproducible developer workstation setup for Debian-based Linux distributions using Nix, Home Manager, and a small system bootstrap script.

The goal is to turn a fresh Debian or Debian-derived Linux installation into a ready-to-use development machine with one command.

## One-command setup

On a fresh Debian-based machine, run:

```bash
curl -fsSL https://raw.githubusercontent.com/sajjadriaj/nix-dev-setup/main/bootstrap.sh | bash
```

The bootstrap installs its own prerequisites, including Git, clones this repository to `~/.local/share/nix-dev-setup`, and installs/configures the workstation.

The only assumptions before running it are Debian or a Debian-derived x86_64 Linux system with `bash`, `apt-get`, `sudo`, systemd, and internet access.

After it completes, log out and back in once so Docker group membership takes effect.

## What it installs

### System layer

- Nix in multi-user/daemon mode
- Docker Engine and systemd service
- Docker user group configuration
- Git, curl, and base bootstrap/build dependencies

### Developer environment

- VS Code
- Node.js 22 and pnpm
- Python 3.12 and uv
- Git, Git LFS, GitHub CLI
- tmux
- zsh, Starship, fzf
- GCC, Clang, CMake, Ninja, Make
- Docker Compose
- kubectl, Helm, k9s
- Terraform
- PostgreSQL and Redis clients
- protobuf and grpcurl
- HTTPie
- ripgrep, fd, jq, yq, bat, eza, tree, htop, btop
- networking/debugging tools
- hey and Vegeta for load testing
- direnv + nix-direnv

### AI coding agents

- Claude Code (`claude`)
- Pi Coding Agent (`pi`)

Both are installed declaratively through Home Manager rather than an ad-hoc global npm installation. Authentication and credentials are intentionally not stored in this repository.

After setup, authenticate Claude Code by running:

```bash
claude
```

For Pi, run:

```bash
pi
```

and use `/login` to connect your preferred provider. Pi's user configuration under `~/.pi/agent` remains mutable so local model/provider settings and credentials can be managed normally.

## Clone-first setup

If you prefer to inspect the repository first:

```bash
git clone https://github.com/sajjadriaj/nix-dev-setup.git
cd nix-dev-setup
chmod +x bootstrap.sh
./bootstrap.sh
```

## Supported systems

The bootstrap targets **x86_64 Debian and Debian-derived Linux distributions** that provide `apt-get`, systemd, and standard Debian package names.

## Updating the workstation

For the default installation:

```bash
cd ~/.local/share/nix-dev-setup
git pull
home-manager switch --flake ".#$USER"
```

Or rerun the one-command bootstrap. An existing managed checkout is fast-forwarded before applying the configuration.

## Configuration layout

```text
nix-dev-setup/
├── bootstrap.sh   # Debian bootstrap, repo setup, Nix and Docker
├── flake.nix      # Nix/Home Manager entry point
├── flake.lock     # generated by Nix
├── home.nix       # persistent developer tools/configuration
├── .gitignore
└── README.md
```

## Adding software

Add packages to `home.packages` in `home.nix`, or use the appropriate Home Manager `programs.*` module when one exists. Then apply:

```bash
home-manager switch --flake ".#$USER"
```

## Notes

- Currently targets x86_64 Debian-based Linux systems.
- VS Code is unfree software, so the flake enables `allowUnfree`.
- Project dependencies should generally remain in project-specific lockfiles (`uv.lock`, `pnpm-lock.yaml`, etc.).
- Secrets, SSH private keys, AI-provider credentials, cloud credentials, and project `.env` files should not be committed to this repository.
