# nix-dev-setup

Reproducible developer workstation setup for Debian-based Linux distributions using Nix, Home Manager, and a small system bootstrap script.

The goal is to turn a fresh Debian or Debian-derived Linux installation into a ready-to-use development machine with one repository and one bootstrap command.

## What it installs

### System layer

`bootstrap.sh` handles software that needs host-level integration:

- Nix in multi-user/daemon mode
- Docker Engine and systemd service
- Docker user group configuration
- Base build/bootstrap dependencies through `apt`

### Nix / Home Manager layer

Persistent user tooling includes:

- VS Code
- Node.js 22 and pnpm
- Python 3.12 and uv
- Git, Git LFS, GitHub CLI
- tmux
- zsh, Starship, fzf
- GCC, Clang, CMake, Ninja, Make
- Docker Compose
- kubectl, Helm, k9s
- Terraform
- PostgreSQL and Redis clients
- protobuf and grpcurl
- HTTPie
- ripgrep, fd, jq, yq, bat, eza, tree, htop, btop
- networking/debugging tools
- hey and Vegeta for load testing
- direnv + nix-direnv

## Fresh machine setup

Clone the repository:

```bash
git clone https://github.com/sajjadriaj/nix-dev-setup.git
cd nix-dev-setup
```

Run:

```bash
chmod +x bootstrap.sh
./bootstrap.sh
```

The script will request `sudo` when system-level changes are required.

After it completes, log out and back in once so Docker group membership takes effect.

## Supported systems

The bootstrap targets **x86_64 Debian and Debian-derived Linux distributions** that provide:

- `apt-get`
- `systemd`
- standard Debian package names used by the bootstrap

Rather than checking for specific distributions such as Ubuntu or Pop!_OS, the script uses `/etc/os-release` and accepts systems identifying themselves as Debian or Debian-derived via `ID` / `ID_LIKE`.

## Updating the workstation

Pull configuration changes:

```bash
cd nix-dev-setup
git pull
```

Then apply them:

```bash
home-manager switch --flake ".#$USER"
```

You can also rerun `./bootstrap.sh`; it skips Nix and Docker installation when they are already present.

## Configuration layout

```text
nix-dev-setup/
├── bootstrap.sh   # Debian system bootstrap: Nix, Docker, base dependencies
├── flake.nix      # Nix/Home Manager entry point
├── flake.lock     # generated by Nix on first flake operation
├── home.nix       # persistent developer applications/configuration
├── .gitignore
└── README.md
```

## Why split bootstrap and Nix?

Nix/Home Manager is excellent for reproducibly managing developer tools and user configuration. Host-level concerns such as the Docker daemon, systemd integration, and initial Nix installation are cleaner to handle through a small distribution-level bootstrap.

`bootstrap.sh` therefore performs the minimum Debian-level system setup required for Nix to take over most of the workstation configuration.

## Adding software

Add packages to `home.packages` in `home.nix`:

```nix
home.packages = with pkgs; [
  vscode
  nodejs_22
  python312
  uv
  # add packages here
];
```

Then apply:

```bash
home-manager switch --flake ".#$USER"
```

## Notes

- Currently targets x86_64 Debian-based Linux systems.
- VS Code is unfree software, so the flake enables `allowUnfree`.
- Application/project dependencies should generally remain in project-specific lockfiles (`uv.lock`, `pnpm-lock.yaml`, etc.) rather than this workstation configuration.
- Secrets, SSH private keys, cloud credentials, and project `.env` files should not be committed to this repository.
